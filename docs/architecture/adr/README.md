# Architecture Decision Records

Short, dated records of significant technical decisions, so future sessions don't re-litigate them.

- One decision per file, numbered `NNNN-title.md`.
- Status: `Proposed` → `Accepted` → `Deprecated` / `Superseded`.
- Don't rewrite an `Accepted` ADR except for typos/links — **supersede** it with a new ADR instead.
- Start from [`0000-template.md`](0000-template.md).
- Write an ADR for: Unity/XR version baselines, DI approach, scene structure, package additions,
  persistence, asset-loading strategy, build pipeline, and any intentional guardrail deviation.
